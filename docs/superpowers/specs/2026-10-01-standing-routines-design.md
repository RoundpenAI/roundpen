# 常驻任务设计

日期：2026-10-01  
状态：待实现。实现计划：`docs/superpowers/plans/2026-10-01-standing-routines.md`  
范围：助手被分配一件反复发生的事之后，到点自己醒来做完，并把结果送回用户。本期落地调度、运行记录、跨次状态、投递和确认闸，以周报类任务为验收。抢券与报税在模型上说清楚，端到端依赖后续的凭据与登录态。

不含自动按简介派活、任务依赖图、凭据库。

## 1. 目标与问题

**问题**

- 今天的助手是会话驱动的：人在控制台或 IM 里开口，它才用搜索、抓页、浏览器、文件和议题工具干活。`automode` 只在一次对话里审批工具，不会到点自己启动。
- 议题（`ISS` / `TSK`）是做一次的工作项。`assistant_id` 记录来源或实现者，议题池按用户共享，没有「这件活归这个助手、以后反复做」的分配。
- 后台 `Bash` 活在某次会话的容器进程里，会话结束就没了，不能当日程。
- IM 是「人发一句、助手回一句」，任务结束不会主动推一条。

**目标**

- 用户对某个助手说「每周一早上发 AI Agent 论文周报」，这句话变成一条常驻任务，到点由**被分配的那个助手**执行。
- 每次执行留下运行记录：做了什么、产物在哪、为什么失败。
- 周与周之间记得已经报过什么，不重复同一批材料。
- 有副作用或不可逆的动作停下来等人，而不是静默做完。

**原则**

1. **助手是负责人，环境是用户的机器。** 常驻任务分配给一个助手。Agent 容器和 Browser 容器仍是该用户的槽位（`user_environments`），不按助手或按任务各开一台。
2. **分配和关联分开。** 分配回答「谁负责」；关联回答「和哪次运行、哪个议题有关」。
3. **对话是入口，DB 是权威。** 跟议题一样：助手在对话里建与改，控制台读写同一份数据。
4. **不破坏安静对话。** 真正干活发生在本次运行自己的会话里。主对话只收一条结果摘要。
5. **常驻任务收不窄助手的边界。** 网络档、能力开关、目录授权仍以助手档案为准。任务只能在这个边界里再收紧。
6. **短 ID 引用。** `RTN-n` / `RUN-n`，人和助手都用它说话。

## 2. 概念

| 概念 | 是什么 | 不是什么 |
|------|--------|----------|
| 常驻任务 Routine | 反复执行的约定：交给谁、何时、做什么、允许做到哪、结果送到哪 | 不是议题，也不是议题下的 `TSK` |
| 运行 Run | 某一次触发的执行：一段会话、一份摘要、一份状态 | 不是助手的主对话本身 |
| 跨次状态 State | 这条任务自己的游标（已见论文、上次覆盖到哪天） | 不是长期记忆，也不是聊天记录 |
| 分配 Assignee | 唯一负责执行的助手 | 不是「谁创建的」——创建者另记 |
| 关联 | 指向某次会话、可选的一个议题 | 不是第二个负责人 |

关系：

```
用户
 └─ 助手（唯一负责人）
     └─ 常驻任务 RTN-n
         ├─ 可选：一个议题 ISS-n（把「先把流程理清」和「以后每月做」分开）
         └─ 运行 RUN-n → 一条执行会话
```

四个例子落到同一模型上，差在自主级别和确认闸，不各做一种任务类型：

| 例子 | 自主级别 | 确认闸 | 本期能否端到端 |
|------|----------|--------|----------------|
| 每周论文周报、投资风向周报 | `read` | 无 | 能。搜索、抓页、写摘要、推送 |
| 定点打开网页抢优惠券 | `browse` | 支付、最终领取若涉及扣款 | 不能。缺站点登录态 |
| 每月报税 | `browse` | **申报提交永远等人** | 不能。缺凭据、票据收件箱、登录态 |

## 3. 与助手的关系

### 3.1 分配

- 一条常驻任务**恰好一个**负责人，字段 `assignee_assistant_id`。
- 对话里创建时，默认负责人是当前会话的助手。系统助手可以提议交给另一个助手，但必须经用户在当轮确认（`AskUserQuestion`）后才能写入别人的 id。
- 本期不做按简介自动匹配。系统助手简介里的「派活能力后续上线」仍然成立。
- 改分配只影响**下一次**运行。已经在跑的 `RUN` 仍由原助手的那条会话做完。
- 负责人被停用或删除：任务自动变为 `paused`，不再唤醒。恢复助手后不自动恢复任务，由用户明确再打开。
- 创建时做能力检查，不满足则拒绝创建并说明原因，不先建成一条永远跑不起来的任务：
  - `read`：助手网络档不是 `none`。
  - `browse`：助手已开 Browser，且网络档不是 `none`。

### 3.2 关联

| 关联 | 基数 | 含义 |
|------|------|------|
| 运行 → 会话 | 一次运行一条 | 这次周报是哪次对话做的。会话软引用，删会话不删运行记录 |
| 常驻任务 → 议题 | 可选，至多一个 | 「把报税流程理清楚」是议题；「以后每月报」是常驻任务。议题做完就关，任务继续按月响 |
| 任务 → 任务 | 无 | 依赖图不在本期 |

`browser_tasks` 仍是一次性的浏览作业，不并入常驻任务。

### 3.3 环境和身份

- 唤醒时 `EnsureAgent` 该用户的 Agent 槽位。`browse` 再 `EnsureBrowser`。
- 执行身份用负责人的 `identityMode`（代理用户 / 独立身份）。密钥仍只在控制面，不进模型。
- 站点账号、Cookie、报税凭据本期没有库。浏览器跑起来也记不住登录。这是抢券和报税留到后续的原因，不是调度模型的缺口。

## 4. 对话里怎么建

跟议题一样：**不擅自创建。** 判据模糊时先问一句。

用户表达「以后反复做」时（每周、每月、每天、到点），助手先用一两轮把下面几件事问清，再调用 `CreateRoutine`：

| 要确定的 | 落点 |
|----------|------|
| 做什么、怎样算做完 | `brief` |
| 交给哪个助手 | `assignee`，默认为当前助手 |
| 何时 | cron + 时区 |
| 允许多深 | `autonomy`：`read` 或 `browse`；`browse` 还要主机列表 |
| 结果送到哪 | 控制台始终有；IM 是否推到负责人已启用的渠道 |

已说死的约束不重复问（「就每周一早上八点，交给你」）。

建完后主对话给短确认：`RTN-n`、负责人、下次运行时间。不在对话里展开调度实现。

暂停、改时间、改分配、归档，用户说了就改，改完一句确认。

## 5. 调度与唤醒

调度器跑在 `roundpend` 里，不跑在 Agent 容器里。

### 5.1 日程

- 一条任务一个 cron（五段：分 时 日 月 周）加一个 IANA 时区。
- 创建时若用户没说时区，用控制台浏览器时区写入；API 创建则时区必填。
- 最小间隔 1 分钟。更密的表达式拒绝。
- 控制台提供预设：每周一 08:00、每月 1 日 09:00、自定义。预设只是填 cron 的入口。
- 存 `next_run_at`（UTC）。每次进入终态后算下一次**未来**的触发点。

### 5.2 错过与重叠

- **补跑至多一次。** 进程或机器当时没起来，若 `now - next_run_at` 不超过宽限，补跑一次，然后跳到再下一次。宽限：周期 ≥ 1 天时为 24 小时，否则等于一个周期。超过宽限不回放中间每一次，记一条 `skipped_stale`，把 `next_run_at` 推到下一个未来点。NAS 停一周，周报补最近这一期，不连补七份。
- **不重叠。** 上次运行还没终态，这次不启动，记 `skipped_overlap`，`next_run_at` 照常推进。

领取到期任务用 `SELECT … FOR UPDATE SKIP LOCKED`，多实例控制面只有一个能领到。

### 5.3 一次运行怎么开始

1. 插入 `runs`，状态 `queued`，然后置 `running`。
2. 按 §3.3 确保环境。
3. 为这次运行**新建**一条 `agent_sessions`，`assistant_id` = 负责人。不占用、不撑爆助手的主会话。
4. 注入固定提示，内容只有：`RTN` / `RUN` 编号、`brief`、自主级别与主机列表、当前 state、上一份成功运行的摘要、本次截止时间。模型用常规模具执行。
5. 运行超过 `max_duration`（默认 15 分钟，创建时可改，上限 60 分钟）仍未结束：取消会话，运行记 `failed`。

### 5.4 一次运行怎么结束

助手调用 `FinishRun`，带摘要和可选产物说明（工作区路径或一段 markdown）。状态 `succeeded`。会话异常退出且没有 `FinishRun`：到期后记 `failed`。

成功或失败后：

- 运行记录写上摘要。
- 若任务要求 IM 且负责人有已启用渠道，把摘要推到那些渠道。
- 往负责人的**主会话**写一条结果消息（做成了什么、`RUN-n`、失败原因）。不回放工具轨迹。主会话当时若正在和用户说话，这条消息照写，不打断当前轮。

## 6. 无人值守与确认闸

自主级别是任务上的收紧，不是助手宪法上的新开关。

| 级别 | 允许 | 不允许 |
|------|------|--------|
| `read` | `WebSearch`、`WebFetch`、工作区读写、更新本任务 state、`FinishRun` | 浏览器、对外发消息（投递由控制面发，不由模型发） |
| `browse` | `read` 的全部，加上 Browser 工具；只能打开任务主机列表里的站点 | 见下方永远停下的动作 |

主机列表与助手网络档取**交集**。任务写了某主机，但助手档不允许，运行期照旧软拒绝，不因为任务提过就放行。

**永远停下、走协助单的动作**（与级别无关，即使用户在 `brief` 里写了「直接提交」）：

- 支付、扣款
- 申报、表单的最终提交
- 删除用户数据
- 向非本任务投递渠道发送消息

助手发协助单（沿用 `assist_tickets`：为什么找你、卡在哪、请你做什么）。运行状态改为 `waiting_user`，`max_duration` 在等待期间暂停计时。用户「继续」后从该会话接着做；「否决」则运行 `failed`，摘要里写明否决原因。等待超过 24 小时没有处置：运行 `failed`，任务本身仍是 `active`，下次照常触发。

人机验证等无法换路的卡壳，同样直接升级协助单（与助手优先设计 §8.4 的例外一致）。

`automode` 仍负责对话中的工具审批。常驻运行默认沿用该助手的 automode；上面这张表是**额外收紧**，automode 批了也不许越出级别。

## 7. 投递与跨次状态

**投递**

- 控制台运行记录始终保存摘要。
- `deliver_im` 默认：负责人有已启用 IM 渠道则为 true，否则 false。推送失败记在运行上，不把整次运行打成失败（周报已经写出来了）。
- 本期没有邮件渠道。

**状态**

- 每条任务一块 JSON state，上限 64KB。助手用 `UpdateRoutineState` 整块替换。
- 只放游标和已见集合这类「下次还要看」的数据。周报正文放在运行摘要和产物里，不塞进 state。
- 长期记忆仍是「知道用户什么」。任务完成后，助手可以另行写入记忆；本期不自动双写。

## 8. 数据模型

### 8.1 键

- 主键 `id` = uuid 字符串。
- `key` = 安装内全局唯一、单调递增、永不复用：`RTN-n` / `RUN-n`。
- 生成与议题相同：序列 `routine_key_seq` / `routine_run_key_seq`，插入时 `'RTN-' || nextval(...)`。
- API 与工具同时接受 `key` 与 uuid。

### 8.2 表

**routines**

| 列 | 说明 |
|----|------|
| `id` / `key` | uuid / `RTN-n` |
| `user_id` | 属主（FK users CASCADE） |
| `assignee_assistant_id` | 负责人（FK assistants）。助手删除时任务改为 `paused` 且本列置空，不级联删任务 |
| `created_by_assistant_id` | 创建时的助手，来源，可空 |
| `created_by_session_id` | 创建时的会话，软引用 |
| `issue_id` | 可选关联议题（FK issues SET NULL） |
| `title` | 短标题 |
| `brief` | 每次运行的说明（markdown） |
| `autonomy` | `read` / `browse` |
| `hosts` | 文本数组。`browse` 必填；`read` 为空 |
| `cron` / `timezone` | 五段 cron / IANA 时区 |
| `deliver_im` | 是否推到负责人的已启用 IM |
| `max_duration_sec` | 默认 900，最大 3600 |
| `state` | jsonb，默认 `{}` |
| `status` | `active` / `paused` / `archived` |
| `next_run_at` | 下次触发（UTC）。`paused` / `archived` 时为空 |
| `created_at` / `updated_at` | |

**routine_runs**

| 列 | 说明 |
|----|------|
| `id` / `key` | uuid / `RUN-n` |
| `routine_id` | FK routines CASCADE |
| `user_id` | 冗余属主 |
| `assistant_id` | 这次实际执行的助手（分配变更后历史仍准） |
| `session_id` | 执行会话，软引用 |
| `status` | `queued` / `running` / `waiting_user` / `succeeded` / `failed` / `skipped_overlap` / `skipped_stale` / `cancelled` |
| `scheduled_at` | 原本的触发时间 |
| `started_at` / `finished_at` | |
| `summary` | 给用户看的结果或失败原因 |
| `artifacts` | jsonb 数组，元素为 `{path}` 或 `{markdown}`，可空 |
| `error` | 内部错误，可空。用户可见的失败原因在 `summary` |
| `deliver_error` | IM 推送失败原因，可空 |
| `assist_ticket_id` | 确认闸挂起时的协助单，可空 |

### 8.3 状态

任务：`active` 会唤醒；`paused` 停唤醒、保留 state；`archived` 停唤醒，并从助手详情的默认列表消失。没有硬删除接口。

运行进入 `succeeded` / `failed` / `skipped_*` / `cancelled` 后不再变。用户取消进行中的运行 → `cancelled`。

## 9. API

| Method | Path | 说明 |
|--------|------|------|
| GET | `/v1/routines?assistantId=&status=&limit=` | 当前用户的任务。默认不含 `archived` |
| POST | `/v1/routines` | 创建。校验分配、自主级别、cron、时区、主机列表 |
| GET | `/v1/routines/{key}` | 任务 + 最近运行（不含 state 以外的大字段；state 包含在内） |
| PATCH | `/v1/routines/{key}` | `title` / `brief` / `autonomy` / `hosts` / `cron` / `timezone` / `deliverIm` / `maxDurationSec` / `status` / `assigneeAssistantId` / `issueKey`。改 cron 或从 `paused` 回到 `active` 时重算 `next_run_at` |
| GET | `/v1/routines/{key}/runs?limit=` | 运行列表，新的在前 |
| GET | `/v1/routines/{key}/runs/{runKey}` | 单次运行 |
| POST | `/v1/routines/{key}/runs/{runKey}/cancel` | 取消非终态运行 |

约定与议题相同：`{key}` 接受短 ID 或 uuid；错误体 `{"error":"..."}`；创建 201；400 / 403 / 404。

助手工具不走「自己指定任意负责人」的裸 POST。见 §10：服务端从会话反查创建者，负责人缺省为该助手，显式指定别人时要求请求带上用户已确认标记。控制台代用户操作，不需要这个标记。

## 10. Agent 工具

注册在 `internal/acp/sysagent/tools`，经现有 HTTP 路径调 API，工具不直连 DB。

| 工具 | Mutating | 参数 | 用途 |
|------|----------|------|------|
| `CreateRoutine` | 是 | `title`, `brief`, `cron`, `timezone`, `autonomy`, `hosts?`, `deliverIm?`, `assigneeAssistantId?`, `issueKey?` | 创建。`assigneeAssistantId` 省略则是当前助手 |
| `ListRoutines` | 否 | `status?` | 列当前用户的任务。负责人是自己的排在前面 |
| `GetRoutine` | 否 | `key` | 任务、state、最近一次运行摘要 |
| `UpdateRoutine` | 是 | `key` + §9 里可改字段 | 暂停、改期、改分配、归档 |
| `UpdateRoutineState` | 是 | `key`, `state` | 整块替换 state。只能改分配给当前助手的任务 |
| `FinishRun` | 是 | `runKey`, `summary`, `artifacts?` | 结束本次运行。只能由该运行的执行会话调用 |

**来源绑定。** 与议题工具相同：注册期绑定当前会话，服务端从 `agent_sessions.assistant_id` 反查创建者。模型不自报「我是哪个助手」。

**指定别人。** `CreateRoutine` / `UpdateRoutine` 的 `assigneeAssistantId` 若不是当前助手，请求必须带 `assigneeConfirmed=true`。这个布尔只表示用户在本轮对话里明确选了这个人；系统提示词要求先 `AskUserQuestion`。它不是安全边界——安全边界是该助手属于同一用户。确认标记用来阻止模型悄悄改派。

**谁能改 state、谁能收工。** `UpdateRoutineState` 要求当前助手是负责人。`FinishRun` 要求当前会话就是该 `RUN` 的 `session_id`。其它工具按用户隔离，负责人可以读用户名下全部任务，避免系统助手看不见别人的任务。

**提示词。** §4 和 §6 的行为写进 System Agent 系统提示词（`internal/acp/sysagent/history.go`）。创建、改派要确认；不可逆动作发协助单而不是继续点。

运行中的工具面在进入会话前按自主级别过滤：`read` 不注册 Browser 工具。这是收紧，不是另一套工具实现。

## 11. 控制台

本期不新增一级导航。常驻任务挂在助手详情里，和「谁负责」一致。

**助手详情新分区「常驻任务」**

- 列表：`RTN-n`、标题、下次运行、状态、最近一次结果一句话。
- 空态：说明可以在对话里交代，例如「每周一早上把 AI Agent 论文发成周报」。
- 新建 / 编辑：标题、说明、预设或 cron、时区、自主级别、主机（`browse` 时）、IM 开关、负责人（默认本助手，可改到自己的其他助手）。
- 暂停、继续、归档。归档需确认。

**运行详情**（详情分区内展开，或 `/a/:assistantId/routines/:key`）

- 说明、分配、日程、state 的只读 JSON。
- 运行列表：时间、状态、摘要。点开可看产物路径与失败原因。
- 进行中：链到该次会话；可取消。
- `waiting_user`：链到对应协助单。

主对话不渲染任务卡片。工具调用仍走现有工具消息。

## 12. 与既有概念的关系

| 既有 | 区别 |
|------|------|
| 议题 / `TSK` | 做一次的步骤，池子按用户共享，`assistant_id` 是来源。常驻任务是反复的约定，且有唯一负责人 |
| `browser_tasks` | 一次性浏览作业，挂在某次会话上 |
| `assist_tickets` | 人在环的裁决。运行撞上确认闸或验证码时开单，单处理完运行才继续或失败 |
| `automode` | 对话内工具审批。常驻运行在其上再按 `read` / `browse` 收紧 |
| 长期记忆 | 用户事实与偏好。跨次游标放在任务 state |
| Skill | 一段可复用指令，没有日程。`brief` 里可以要求运行开始时调用某个技能；技能本身不会到点启动 |
| 后台 Bash | 会话内的临时进程，不是日程 |
| 系统助手「派活」 | 本期只允许在用户确认后把负责人写成另一个助手。不按简介自动选择 |

## 13. 权限与隔离

- 查询在 SQL 层按 `user_id` 过滤。一个用户不能看见或改派另一个用户的助手。
- 助手工具的 actor 是该用户，因此只能动自己的任务。
- 执行会话的工具权限与该助手平时相同，再叠加 §6 的收紧。
- state 和摘要按用户数据存储。控制台展示摘要时走已有的 Markdown 渲染，不注入原始 HTML。

## 14. 本期与后续

**本期要落地**

- 本规格的表、API、工具、调度器、运行会话、IM 与主会话摘要、助手详情分区。
- 验收场景：对一个开了网络的助手说「每周一 08:00 汇总过去七天 AI Agent 相关论文，发成周报」。到点（或测试里手动把 `next_run_at` 拨到过去）它自己跑完，IM 或主会话收到摘要，第二次运行能从 state 里避开已报过的条目。投资风向周报是同一条路径，只是 `brief` 不同。

**后续，本规格不实现**

- 凭据库、浏览器登录态。有了之后，抢券和报税填表才使用已有的 `browse` 与确认闸，不再改分配模型。
- 按简介自动派活。
- 任务之间的依赖。
- 按 token 的预算（本期只有墙钟 `max_duration`）。
- 秒级触发、邮件投递。

## 15. 非目标

- 一条任务多个负责人，或一次运行扇出给多个助手。
- 把常驻任务做成看板、优先级、标签。
- 硬删除与回收站。
- 在 Agent 容器里跑 cron。
- 为论文源、券站点、税务局各写一套专用连接器。来源写在 `brief` 里，用现有搜索、抓页和浏览器工具。
- 无人确认的支付、扣款、申报提交。

## 16. 成功标准

- 用户对助手说每周做一次周报，确认后得到 `RTN-n`。助手详情能看到负责人和下次时间。
- 没有人发消息时，到点仍会跑。主对话只有一条结果，工具过程在该次运行的会话里。
- 机器错过一个周期：宽限内补跑一次；停更久则记 `skipped_stale`，不连补。
- 上次还在跑时，新的触发记 `skipped_overlap`。
- 负责人没有 Browser 时，建不成 `browse` 任务。
- 运行期遇到提交、支付一类动作时进入 `waiting_user`，不继续点完成。
- 改分配后，下一次运行的 `assistant_id` 是新助手，历史运行仍显示旧助手。
