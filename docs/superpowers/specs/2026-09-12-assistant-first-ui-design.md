# 助手优先的产品界面设计

日期：2026-09-12  
状态：已对齐，待实现计划  
范围：Roundpen Web 控制台的用户心智与界面信息架构（不含具体视觉稿与 API 详设）

## 1. 目标与原则

Roundpen 底层由 Docker / VM 等 Sandbox 支撑 Agent 安全运行，但对用户**不暴露 Sandbox 概念**。用户创建和管理的是**助手**：能看见什么、能做什么、以谁的身份对外。

**交互总原则**

- **授权范围内**：安静执行，进度写入活动日志，不在对话里逐步汇报。
- **越权或无法自助**：由助手决定是否向人类发起**协助单**（策略软拒绝不自动刷单）。
- **人想巡视**：进入助手详情看「此刻」与边界配置，而不是让对话变成直播间。

**已选整体骨架：安静搭档（方案 1）**

- 侧边助手列表（联系人式）+ 主区对话。
- 顶栏「待处理」聚合协助单。
- 点助手进入详情（完整可编辑档案 + 此刻）。

## 2. 产品决策摘要

| 主题 | 决策 |
|------|------|
| 主对象 | 助手优先；对话 / 浏览器 / 文件等均为助手服务 |
| 日常首页 | 默认进入主助手对话；侧边切换助手 |
| 创建 | 三问：名称与简介 → 身份 → 能力预设；其余用安全默认 |
| 身份 | 整助手二选一：代理我 / 独立身份；切换为高风险操作 |
| 可见范围 | 默认隔离工作区；本机目录按需授权 |
| 能力 | 助手上的开关（Shell / Browser / Mobile / Desktop…） |
| 网络 | 三档（禁止 / 常用开发站 / 全部）+ 高级白名单 |
| 运行时 | 用户不选；平台自带 runtime（当前 Claude Code / ACP）；架构预留日后高级可换 |
| 监督 | 对话安静；详情「此刻」可看在干嘛 |
| 升级人类 | 协助单（会话内权威）+ 顶栏待处理轻量聚合 |
| 简介 | 派活匹配信号，强烈建议填写 |

## 3. 信息架构与导航

### 3.1 用户可见结构

| 区域 | 内容 |
|------|------|
| 左侧 | 助手列表（当前高亮、新建入口）；副标题展示简介摘要 |
| 主区 | 与当前助手的对话（默认安静） |
| 顶栏 | 产品名、待处理数量、账号 / 设置 |
| 助手入口 | 头像 / 名称 → 助手详情 |

本期以**一助手一条主对话时间线**为主；历史任务与动作在详情「此刻 / 历史」查看。不把「多会话列表」做成与助手同级的导航，避免回到「先选会话再选环境」的旧心智。

### 3.2 不对普通用户做一级导航的概念

Sandbox、Environment、槽位、QEMU、镜像 / Registry。运维与 admin 能力放在设置的高级区（若仍需私有化运维入口）。

### 3.3 账号级设置（非助手）

登录与安全、可用于「代理我」的账号连接、待处理通知偏好、admin 的镜像与引擎只读/管理。

## 4. 助手详情（完整档案）

同一页分区，默认可查看，点编辑再改。用词用人话，不出现 Sandbox / 挂载 / 槽位。

| 分区 | 展示 | 可编辑 |
|------|------|--------|
| 基本信息 | 名称、简介、创建时间、状态（空闲 / 工作中 / 等待你） | 名称、简介；停用 / 删除 |
| 此刻 | 进行中任务、动作时间线；可选「打开画面」 | 主要只读；取消任务；跳转协助单 |
| 可见范围 | 默认工作区说明 + 已授权本机目录（只读/读写） | 添加 / 移除授权、改权限 |
| 能力清单 | Shell / Browser / Mobile / Desktop… | 开关；未就绪项显示即将推出 |
| 网络 | 当前档 + 高级白名单入口 | 改档、编辑白名单 |
| 身份绑定 | 代理我或独立身份 + 已连接渠道 | 按模式管理绑定；模式切换需二次确认 |

## 5. 创建助手

### 5.1 三步

1. **怎么称呼它**  
   - 名称（必填）  
   - 简介（强烈建议）：擅长什么、负责范围、不适合什么  
   - 帮助文案大意：简介用于以后给多个助手派活时匹配最合适的人选；写得越具体越不容易派错。  
   - 允许暂空以求快；列表对空简介给轻提示「补充简介以便派活」。

2. **它以谁的名义对外**（二选一大卡片）  
   - **代理我**：对外动作用用户账号。  
   - **独立身份**：助手自有账号包。  
   - 每卡一行后果说明（例如提交显示为谁）。

3. **先具备哪些能力**  
   - 推荐预设（如写作与文件 / 代码含终端 / 代码 + 浏览器），本质是能力开关组合，可展开自定义。

### 5.2 创建后的默认

- 隔离工作区已就绪。  
- 网络默认「常用开发站」。  
- 进入与该助手的对话。  
- 目录授权、细白名单、账号连接在详情按需完成，不堵在创建门上。  
- 不选择 runtime。

## 6. 身份绑定

| 模式 | 界面逻辑 |
|------|----------|
| 代理我 | 「使用我的账号」；连接指向用户的 GitHub / Email / 社交等 |
| 独立身份 | 「助手自己的账号」；每渠道为它连接 / 断开；可显示对外显示名 |

规则：

- 未连接渠道 ≠ 关闭能力：仍可浏览等；「以谁登录 / 发信」取决于绑定。  
- 缺身份又必须对外时：助手可发起协助单（连接账号或协助视图内登录），而非在对话刷失败日志。  
- 代理我 ↔ 独立身份切换：高风险确认（已绑定渠道失效或需重连）。

## 7. 安静对话、此刻、协助单

### 7.1 对话

- 下任务 → 短确认（理解与边界）→ 授权内执行期间**不刷工具逐步进度**。  
- 结束：一条结果摘要（做成了什么、产出在哪）；可链到详情历史。  
- 进行中：轻状态「工作中」；点状态或助手名进详情。

### 7.2 详情「此刻」

- 当前任务标题与开始时间。  
- 动作时间线（日志语气）。  
- 有画面时提供「打开画面」（非常驻侧栏）。  
- 取消任务；跳转未完成协助单。

### 7.3 协助单

**何时出现（人类侧）**

- 助手**明确发起**的申请（目录 / 能力 / 网络等软拒绝之后）。  
- 无法自助的卡壳（如 Cloudflare 验证码）——可直接升级或由助手立即提「需要你完成验证」单。  
- 其他高风险动作（实现计划中枚举，例如大规模删除、对外群发）；这类应走明确申请，不得在授权内静默执行。

**单内要素**

1. 为什么找你  
2. 卡在哪（摘要）  
3. 请你做什么  
4. **打开协助** → 临时协助视图（浏览器 / 桌面或确认面板）  
5. **继续** / **否决并说明**

对话里只反映单的状态变化（待处理 → 已处理），不刷协助过程细节。过程写入活动日志。

### 7.4 待处理（顶栏）

- 数字 = 各助手未处理协助单之和。  
- 点开：按助手分组短列表 → 进入该助手对话中的对应单（会话内单为权威上下文）。

### 7.5 行为对照

| 情况 | 对话 | 详情「此刻」 | 协助单 |
|------|------|--------------|--------|
| 授权内推进 | 安静 | 可查日志 | 无 |
| 完成 | 结果摘要 | 归档历史 | 无 |
| 人想巡视 | 不打扰 | 主动打开 | 无 |
| 策略软拒绝 | 不自动找人 | 记录拦截 | 仅当助手申请后 |
| 验证码等无法自助 | 出现协助单 | 同步可见 | 有 |

## 8. 可见范围、能力、网络与升级咬合

改边界对后续动作生效。进行中任务若冲突：说明并请用户选择继续或重来（可通过协助单或详情操作）。

### 8.1 可见范围

- 默认：仅助手可见的隔离工作区。  
- 列表管理已授权本机目录（路径、只读/读写）。  
- 添加时风险提示；移除后不可再访；若当前任务占用则暂停并说明。

### 8.2 能力清单

- 每项：名称、一句话说明、开关。  
- 关闭时若有依赖任务：提示取消或降级。  
- Mobile / Desktop 未就绪：即将推出，不可开。

### 8.3 网络

- 三档：禁止上网 / 常用开发站（可只读查看默认集；具体域名清单由平台维护，本规格不展开）/ 允许全部（二次确认）。  
- 高级白名单：文案写清与当前档的关系（收紧或例外），避免与三档语义打架。

### 8.4 软拒绝 → 可申请（不自动找人）

适用于：**未允许的域名 / 网络档、未授权目录、未开启能力**。

1. 运行时返回给助手：策略禁止、短原因、**可申请**（允许一次 / 写入档案）。  
2. **不**自动生成人类协助单。  
3. 助手自行换路、放弃，或**明确发起申请**后才出现协助单。  
4. 申请须写清目标与建议处置；「此刻」仍记录每次拦截供审计。

**例外**：人机验证等无法换路的情况，可以直接升级人类。

### 8.5 协助单上的处置必须区分

| 按钮 | 含义 |
|------|------|
| 允许一次 | 不改宪法，只放行本次 |
| 永久授权 / 打开能力 / 加入白名单 / 改网络档 | 写回详情对应项，并继续任务 |
| 拒绝 | 助手停止该路径并记录原因 |

避免「到底以后还能不能」的歧义。

## 9. 运行时

- 普通用户**不选择** Codex / OpenCode 等引擎。  
- 助手由 Roundpen 自带 runtime 执行（当前为 Claude Code via ACP）。  
- 详情可不强调引擎；admin / 高级可只读标明。  
- 实现上预留日后「高级可换 runtime」（产品决策 C 的演进），但不进入本期创建流。

## 10. 用户概念与底层映射

| 用户说的 | 底层大致是 |
|----------|------------|
| 助手 | 带策略档案的 Agent 主体 + 会话；平台 runtime 执行 |
| 默认工作区 | 隔离环境中的工作区（如 `/workspace`） |
| 授权本机目录 | 受控挂载或文件代理（只读/读写） |
| 能力开关 | 是否 ensure 对应环境与工具 |
| 网络三档 + 白名单 | Egress / 代理策略；拒绝返回「可申请」 |
| 代理我 / 独立身份 | 凭证归属用户 vs 助手；控制面代理，密钥不进模型 |
| 此刻 / 活动日志 | 审计与工具轨迹 |
| 协助单 | 人在环工单 + 可选协助视图 |
| 简介 | 派活匹配信号（人工选择 + 未来自动派活） |

## 11. 文案禁词

| 避免 | 改用 |
|------|------|
| Sandbox / 沙箱 | （不提；说工作区 / 助手） |
| 挂载 / mount | 授权文件夹 / 可见范围 |
| Egress / 出站 | 网络访问 / 允许访问的网站 |
| Runtime / 引擎（对普通用户） | 不提，或「由 Roundpen 运行」 |
| Token / 注入凭证 | 连接账号 / 身份绑定 |
| 槽位 / 环境机 | 能力（浏览器、终端…） |

## 12. 非目标（本期界面设计不覆盖）

- 具体视觉设计系统与动效。  
- API / 数据库 schema 详设。  
- 自动派活算法（仅要求简介作为匹配输入成立）。  
- 多用户协作同一助手、计费、市场模板商店。  
- 将 admin 镜像构建流程产品化到普通用户导航。

## 13. 成功标准（体验）

- 新用户能在不理解 Docker/VM 的情况下创建助手并下发任务。  
- 用户能一句话说清某助手：是谁的身份、能碰哪些东西、有哪些能力、网络多严。  
- 授权内工作时对话保持干净；需要人时有可操作的协助单，且策略拦截不会刷爆待处理。  
- 想监督时，详情「此刻」可回答「它在干嘛」。
